# Полная русская локализация WORLD OF HORROR

## Установка

Нужны [uv](https://docs.astral.sh/uv/getting-started/installation/) и консольная версия [UndertaleModTool](https://github.com/UnderminersTeam/UndertaleModTool) (`UndertaleModCli`).

Python и зависимости ставить отдельно не нужно: `uv` сам скачает интерпретатор (3.12 или новее) и всё, что скрипт объявляет в заголовке. Запускайте скрипты через `uv run` из корня репозитория.

Установите `uv` один раз:

```bash
# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Укажите путь к `UndertaleModCli` и запустите установку из корня репозитория:

```bash
# Windows
$env:UTMT_CLI = "C:\путь\к\UndertaleModCli.exe"
uv run woh.py build

# Linux
UTMT_CLI=/путь/к/UndertaleModCli uv run woh.py build
```

Скрипт соберёт файлы локализации, пропатченный `worldofhorror.exe` и новый `data.win` с переведёнными картинками и шрифтами в папку `output/`. Папку игры он не меняет: скопируйте `output/language/engLanguage/*.jn` в `language/engLanguage/`, а `data.win` и `worldofhorror.exe` в корень папки игры.

Игра ищется в стандартной папке Steam:

- Windows: `C:\Program Files (x86)\Steam\steamapps\common\WOH`
- Linux: `~/.local/share/Steam/steamapps/common/WOH`

Если игра установлена в другое место, укажите её папку: `woh.py --game "ПАПКА" build`.

### Текст, зашитый в исполняемый файл

Часть текста находится не в файлах локализации, а в самом `worldofhorror.exe`. Команда `woh.py build` патчит exe файл.

Для патча нужны [Ghidra](https://ghidra-sre.org/) (путь к `analyzeHeadless` в переменной `GHIDRA_HEADLESS`) и `clang`. Первый анализ игры занимает десятки минут, но его результат сохраняется.

## Команды

Все команды запускаются как `uv run woh.py [--game ПАПКА] <команда>`. Каждая сама собирает всё, что ей нужно и чего ещё нет.

| Команда              | Что делает                                                                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build`              | Собирает всё в папку `output/`, не трогая игру; отказывается писать, если exe, исходные кадры или шрифты переведённых картинок изменились с тех пор, как их хеши записаны в `hashes.txt` |
| `build --no-exe`     | То же, но без пропатченного `worldofhorror.exe`                                                                                                                                          |
| `build --no-text`    | То же, но без файлов локализации                                                                                                                                                         |
| `build --no-sprites` | То же, но без `data.win`                                                                                                                                                                 |
| `build --bundle`     | То же, но дополнительно собирает в корне проекта `<версия>.zip` (обычный zip, deflate) с установщиком `wohrus`, списком изменений и `THIRD-PARTY-NOTICE.md` (лицензии Rust-библиотек установщика, `cargo-about`). Установщик содержит патчи (bsdiff) к `data.win` и exe плюс остальные файлы `output/`, около 1,5 МБ вместо ~230 МБ |
| `sync`               | Обновляет файлы перевода после обновления игры, сохраняя готовый перевод; для exe пишет список новых текстов                                                                             |
| `hashes`             | Принимает текущие файлы игры: записывает в `hashes.txt` их хеши (после обновления игры, когда переводы изменившихся файлов проверены); без этого `build` отказывается писать             |
| `extract`            | Извлекает все кадры и шрифты в `img/source/`                                                                                                                                             |
| `ocr`                | Распознаёт текст на извлечённых кадрах                                                                                                                                                   |
| `save [ФАЙЛ] ВЫХОД`  | Создаёт сохранение со всем открытым, для проверки перевода                                                                                                                               |
| `check`              | Проверяет размеры картинок и патч                                                                                                                                                        |
| `list`               | Показывает все этапы сборки                                                                                                                                                              |

Пути к инструментам задаются переменными окружения: `UTMT_CLI`, `GHIDRA_HEADLESS`, `WOH_GHIDRA_JAVA` (`JAVA_HOME` для Ghidra).

## Строение репозитория

| Путь                          | Содержимое                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `woh.py`                      | Точка входа: все команды запускаются через него                                                                     |
| `translation/*.txt`           | Перевод игрового текста                                                                                             |
| `translation/exe_strings.txt` | Перевод текста из `worldofhorror.exe`                                                                               |
| `img/translation/`            | Переведённые картинки, `.png` и исходники `.psd`. Их можно открыть в любом подходящем приложении (Photoshop, Krita) |
| `pipeline/reverse/`           | Шаг 1: анализ установленной версии игры                                                                             |
| `pipeline/generate/`          | Шаг 2: создание нужных для сборки файлов                                                                            |
| `pipeline/act/`               | Шаг 3: сборка перевода, сохранений и картинок                                                                       |
| `pipeline/check/`             | Проверки                                                                                                            |
| `pipeline/README.md`          | Устройство скриптов и заметки по реверс-инжинирингу игры (на английском)                                            |

В репозитории хранятся только скрипты и то, что сделано вручную. Всё остальное создаётся заново и не отслеживается:

- `build/`: результаты анализа, отдельно для каждой версии игры
- `output/`: собранный перевод
- `img/source/`: извлечённые из игры кадры и атласы шрифтов (`font/`)

## Как устроены файлы перевода

Файлы в `translation/` состоят из строк вида `английский текст|русский текст`:

- Символ `#` обозначает перенос строки.
- Английскую часть менять нельзя: по ней перевод сопоставляется со строками игры.
- `exe_strings.txt` устроен иначе, см. ниже.

### Как заполнять `exe_strings.txt`

Здесь лежит перевод текста, зашитого прямо в `worldofhorror.exe`. Файл ведётся вручную, и в нём только переведённые строки: `sync` его не меняет.

Формат строки: `[!]английский текст|русский текст`.

- Английская часть должна совпадать с текстом в exe байт в байт, включая пробелы по краям и регистр.
- Спецсимволы: `\n` — перенос строки игры (CRLF), `\l` — одиночный LF, `\r` — одиночный CR, `\t` — табуляция, `\\` — обратная косая черта. Если английский текст сам начинается с `!`, пишите `\!`.
- Первые четыре строки (`DOOM`, `STA`, `REA`, `ALL`) — подписи типа урона на экране боя. Они работают по-своему, и `!` им не нужен.

**Где брать новые тексты.** `uv run woh.py sync` пишет в `build/<версия>/out/exe_strings_candidates.txt` все тексты exe, которых ещё нет в файле, уже в виде `текст|`. Туда же попадает мусор: служебные строки, отладка, тексты, которые игра не показывает. Переносите только то, что видели в игре. Тот же `sync` перечисляет строки файла, которых нет в текущей версии exe: после обновления игры их нужно найти заново или удалить.

**Без `!` (по умолчанию, безопасно).** Перевод подставляется только в момент, когда игра рисует этот текст целиком. Сравнения, сохранения и всё остальное видят английский текст, поэтому сломать игру так нельзя. Если текст в игре остался английским, значит, игра склеивает его из кусков (`"[" + "rolled" + ": " + число`) или меняет перед отрисовкой, и нужен `!`. Если склейка всегда даёт один и тот же текст, вместо `!` можно добавить без `!` её готовый результат целиком: так переведены строки консоли `…Initializing STEAM... DONE` и `…SKIPPED`.

**С `!` (`!rolled|выпавшее число`).** Перевод заменяет сам текст в exe, поэтому работает, если текст, например, используется в конкатенации. Но если код использует этот текст как ключ (сравнивает, собирает из него имя переменной, хранит в сохранении), игра сломается. Так `fearful|ужас` с заменой оставлял переменную `status_fearful` пустой, и бои в игре ломались. Порядок действий:

1. Добавьте строку без `!` и проверьте в игре.
2. Если текст не перевёлся, поставьте `!` и запустите `build`. Сборка останавливается с сообщением `marked ! but compared by the game`, если анализ видит, что код сравнивает этот текст. Тогда снимите `!`: такой текст переводить заменой нельзя.
3. Анализ ловит не всё. Тексты, похожие на ключи (имена персонажей, мест, статусов, предметов строчными буквами), оставляйте без `!`, если не уверены. После сборки пройдите место в игре, где текст используется.

Новая картинка должна называться так же, как кадр игры (`<спрайт>_<кадр>.png`), и иметь тот же размер. Лист шрифта тоже должен совпадать по размеру с оригиналом.
